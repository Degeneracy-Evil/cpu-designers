## 第31章 "V" 标准扩展，向量操作，版本 1.0

_基本向量扩展旨在为 32 位指令编码空间内的数据并行执行提供通用支持，后续向量扩展将为特定领域提供更丰富的功能。_

## 31.1. 引言

第 31.18 节列出了标准向量扩展以及每个扩展支持的指令和元素宽度。

## 31.2. 实现定义的常量参数

每个支持向量扩展的 hart 定义了两个参数：

1. 任何操作可以产生或消耗的向量元素的最大位宽，_ELEN_ ≥ 8，必须是 2 的幂。
2. 单个向量寄存器的位数，_VLEN_ ≥ ELEN，必须是 2 的幂，且不大于 2[16]。

标准向量扩展（第 31.18 节）和体系结构配置文件可能会对 _ELEN_ 和 _VLEN_ 设置进一步的约束。

**评论：** _未来的扩展可能允许 ELEN > VLEN，即使用多个向量寄存器的位来存放一个元素，但本扩展不包含此选项。_

**评论：** _VLEN 的上限允许软件知道索引将适合 16 位（最大 VLMAX 为 65,536，对应于 LMUL=8、SEW=8、VLEN=65,536）。任何超出每个向量寄存器 64Kib 的未来扩展都需要新的配置指令，以便使用旧配置指令的软件不会看到更大的向量长度。_

向量扩展支持编写二进制代码，在满足一定约束条件的情况下，该代码可在具有不同 VLEN 参数值的 hart 上可移植地执行，前提是这些 hart 支持所需的元素类型和指令。

**评论：** _可以编写能够暴露实现参数差异的代码。_

## 31.3.1. 向量寄存器

向量扩展向基本标量 RISC-V ISA 添加了 32 个架构向量寄存器 `v0` - `v31`。

每个向量寄存器具有固定的 VLEN 位状态。

## 31.3.2. **`mstatus`** 中的向量上下文状态

向量上下文状态字段 `VS` 被添加到 `mstatus[10:9]` 并影子映射到 `sstatus[10:9]`。其定义与浮点上下文状态字段 `FS` 类似。

当 `mstatus.VS` 设置为 Off 时，尝试执行任何向量指令或访问向量 CSR 将引发非法指令异常。

当 `mstatus.VS` 设置为 Initial 或 Clean 时，执行任何更改向量状态（包括向量 CSR）的指令将把 `mstatus.VS` 更改为 Dirty。实现也可以在任何时候将 `mstatus.VS` 从 Initial 或 Clean 更改为 Dirty，即使向量状态没有变化。

**评论：** _`mstatus.VS` 是上下文切换开销的精确设置，是一种优化。软件通常使用 VS 来减少开销。_

如果 `mstatus.VS` 为 Dirty，则 `mstatus.SD` 为 1；否则，`mstatus.SD` 根据现有规范设置。

实现可以具有可写的 `misa.V` 字段。与浮点单元的处理方式类似，即使 `misa.V` 清零，`mstatus.VS` 字段也可以存在。

**评论：** _允许在_ `misa.V` _清零时存在_ `mstatus.VS` _，可以支持向量仿真并简化具有可写_ `misa.V` _的系统中_ `mstatus.VS` _的处理。_

## 31.3.3. **`vsstatus`** 中的向量上下文状态

当存在 hypervisor 扩展时，向量上下文状态字段 `VS` 被添加到 `vsstatus[10:9]`。其定义与浮点上下文状态字段 `FS` 类似。

当 V=1 时，`vsstatus.VS` 和 `mstatus.VS` 同时生效：当任一字段设置为 Off 时，尝试执行任何向量指令或访问向量 CSR 将引发非法指令异常。

当 V=1 且 `vsstatus.VS` 和 `mstatus.VS` 均未设置为 Off 时，执行任何更改向量状态（包括向量 CSR）的指令将把 `mstatus.VS` 和 `vsstatus.VS` 都更改为 Dirty。实现也可以在任何时候将 `mstatus.VS` 或 `vsstatus.VS` 从 Initial 或 Clean 更改为 Dirty，即使向量状态没有变化。

## 31.3.4. 向量类型（ **`vtype`** ）寄存器

## 31.3.4.2. 向量寄存器分组（ **`vlmul[2:0]`** ）

多个向量寄存器可以分组在一起，使得单条向量指令可以操作多个向量寄存器。本文使用术语_向量寄存器组_来指代用作向量指令单个操作数的一个或多个向量寄存器。向量寄存器组可用于为更长的应用向量提供更高的执行效率，但其主要包含原因是允许双倍宽度或更大的元素以与单倍宽度元素相同的向量长度进行操作。向量长度乘数 _LMUL_ 在大于 1 时，表示组合形成向量寄存器组的向量寄存器的默认数量。实现必须支持 LMUL 整数值 1、2、4 和 8。

**评论：** _向量体系结构包含的指令可以接受不同元素宽度但相同元素数量的多个源和目的向量操作数。每个向量操作数的有效 LMUL (EMUL) 由存放元素所需的寄存器数量决定。_

**评论：** _例如，对于加宽加法操作，如将 32 位值相加以产生 64 位结果，双倍宽度的结果需要单倍宽度输入两倍的 LMUL。_

LMUL 也可以是分数值，减少单个向量寄存器中使用的位数。分数 LMUL 用于在操作混合宽度值时增加有效可用的向量寄存器组数量。

**评论：** _仅使用整数 LMUL 值，操作一定大小范围的循环将不得不为最窄的数据类型至少分配一个完整的向量寄存器（LMUL=1），然后为每个更宽的向量操作数消耗多个向量寄存器（LMUL>1）来形成向量寄存器组。这会限制可用的向量寄存器组数量。使用分数 LMUL，最宽的值只需要占用一个向量寄存器，而较窄的值可以占用单个向量寄存器的分数部分，从而允许所有 32 个架构向量寄存器名称在向量循环中用于不同的值，即使在处理混合宽度值时也是如此。分数 LMUL 意味着部分向量寄存器未被使用，但在某些情况下，拥有更多较短的寄存器驻留向量比拥有更少较长的寄存器驻留向量效率更高。_

实现必须提供分数 LMUL 设置，使得最窄支持的类型能够占用与最宽支持类型宽度对最窄支持类型宽度之比相对应的向量寄存器分数。一般来说，要求是支持 LMUL ≥ SEWMIN/ELEN，其中 SEWMIN 是最窄支持的 SEW 值，ELEN 是最宽支持的 SEW 值。在标准扩展中，SEWMIN=8。对于 ELEN=32 的标准向量扩展，必须支持 1/2 和 1/4 的分数 LMUL。对于 ELEN=64 的标准向量扩展，必须支持 1/2、1/4 和 1/8 的分数 LMUL。

**评论：** _当 LMUL < SEWMIN/ELEN 时，不能保证实现有足够的位在分数向量寄存器中存储至少一个元素，因为 VLEN=ELEN 是一个有效的实现选择。例如，VLEN=ELEN=32 且 SEWMIN=8 时，LMUL 为 1/8 将仅在向量寄存器中提供四位存储空间。_

对于给定的支持的分数 LMUL 设置，实现必须支持 SEW 设置在 SEWMIN 和 LMUL * ELEN 之间（含）。

使用 LMUL < SEWMIN/ELEN 的 `vtype` 编码是_保留_的，但如果实现不支持这些配置，可以设置 `vill`。

**评论：** _要求所有实现都在此情况下设置_ `vill` _将禁止未来扩展中使用此情况，因此为允许未来定义 LMUL<SEWMIN/ELEN 的行为，我们认为此情况的使用是保留的。_

**评论：** _建议汇编器在_ `vsetvli` _指令尝试写入 LMUL < SEWMIN/ELEN 时提供警告（而非错误）。_

## 31.3.4.3. 向量尾部未知和向量掩码未知 **`vta`** 和 **`vma`**

这两个位分别修改向量指令执行期间目的尾部元素和目的非活跃掩码关闭元素的行为。尾部集合和非活跃集合包含在向量操作期间不接收新结果的元素位置，如第 31.5.4 节所定义。

所有系统必须支持所有四种选项：

|`vta`|`vma`|尾部元素|非活跃元素|
|---|---|---|---|
|0|0|保留不变|保留不变|
|0|1|保留不变|未知|
|1|0|未知|保留不变|
|1|1|未知|未知|

掩码目的尾部元素始终视为尾部未知，与 `vta` 的设置无关。

当集合标记为保留不变时，向量寄存器组中对应的目的元素保留其先前持有的值。

当集合标记为未知时，任何向量目的操作数中对应的目的元素可以保留其先前持有的值，或者被覆写为 1。在单条向量指令内，每个目的元素可以保持不被改动或被覆写为 1，可以是任意组合，且不被改动或覆写为 1 的模式在指令以相同输入执行时不需要是确定性的。

**评论：** _添加未知策略是为了适应具有向量寄存器重命名的机器。使用保留不变策略，所有元素都必须从旧物理目的向量寄存器中读出以复制到新物理目的向量寄存器中。当后续计算不需要这些非活跃或尾部值时，这会造成效率低下。_

**评论：** _选择覆写值为全 1 而非全 0 是为了阻止软件开发者依赖于写入的值。_

**评论：** _简单的顺序实现可以忽略这些设置，直接使用保留不变策略执行所有向量指令。但_ `vta` _和_ `vma` _状态位仍必须提供在_ `vtype` _中以实现兼容性并支持线程迁移。_

**评论：** _乱序实现可以选择使用尾部未知+掩码保留不变来实现尾部未知+掩码未知，以降低实现复杂度。_

**评论：** _未知结果策略的定义被保留得较为宽松，以适应在小型顺序核心（可能使未知区域保持不被改动）和具有寄存器重命名的较大乱序核心（可能用 1 覆写未知元素）的 hart 之间迁移应用线程。由于可能需要在中途重启，我们允许在单条向量指令内任意混合未知策略。这种允许混合策略的方式也使得实现可以为向量寄存器的不同粒度更改策略，例如，在正在操作的粒度内使用保留不变，但对尾部中的粒度重命名为全 1。_

此外，除了掩码加载指令外，掩码结果的尾部中的任何元素也可以被写为掩码产生操作在 `vl` =VLMAX 时计算出的值。进一步，对于掩码逻辑指令和 `vmsbf.m` 、 `vmsif.m` 、 `vmsof.m` 掩码操作指令，结果的尾部中的任何元素可以被写为掩码产生操作在 `vl` =VLEN、SEW=8、LMUL=8 时计算出的值（即掩码寄存器的所有位都可以被覆写）。

**评论：** _掩码尾部始终视为未知，以减少管理掩码数据的复杂性，掩码数据可以按位粒度写入。软件似乎很少需要支持掩码寄存器值的尾部保留不变。允许掩码产生指令写回指令结果避免了对尾部进行掩码处理的逻辑需求，但掩码加载不能将内存值写入目的掩码尾部，因为这会意味着访问超出软件意图的内存。_

汇编语法为 `vsetvli` 指令添加了两个必需标志：

```
 ta   # 尾部未知
 tu   # 尾部保留不变
 ma   # 掩码未知
 mu   # 掩码保留不变
 vsetvli t0, a0, e32, m4, ta, ma   # 尾部未知，掩码未知
 vsetvli t0, a0, e32, m4, tu, ma   # 尾部保留不变，掩码未知
 vsetvli t0, a0, e32, m4, ta, mu   # 尾部未知，掩码保留不变
 vsetvli t0, a0, e32, m4, tu, mu   # 尾部保留不变，掩码保留不变
```

**评论：** _在 v0.9 之前，当在_ `vsetvli` _上未指定这些标志时，它们默认为掩码保留不变/尾部保留不变。然而，使用不带这些标志的_ `vsetvli` _已被弃用，现在必须指定标志设置。默认值可能应该是尾部未知/掩码未知，这样软件就必须在关心非参与元素时指定，但考虑到引入这些标志之前该指令的历史含义，决定在未来的汇编代码中始终要求使用它们。_

## 31.3.4.4. 向量类型非法（ **`vill`** ）

**评论：** _`vill` 位保存在 CSR 的 XLEN-1 位，以支持通过符号位分支来检查非法值。_

## 31.3.5. 向量长度（ **`vl`** ）寄存器

_XLEN_ 位宽的只读 `vl` CSR 只能由 `vset{i}vl{i}` 指令和_仅首故障_向量加载指令变体更新。

`vl` 寄存器保存一个无符号整数，指定向量指令将更新结果的元素数量，详见第 31.5.4 节。

**评论：** _`vl` 中实现的位数取决于实现的最小支持类型的最大向量长度。具有 VLEN=32 且支持 SEW=8 的最小向量实现至少需要在_ `vl` _中使用六位来保存值 0-32（VLEN=32，LMUL=8，SEW=8，产生 VLMAX=32）。_

## 31.3.6. 向量字节长度（ **`vlenb`** ）寄存器

_XLEN_ 位宽的只读 CSR `vlenb` 保存值 VLEN/8，即向量寄存器长度（以字节为单位）。

**评论：** _`vlenb` 中的值在任何实现中都是设计时常量。_

**评论：** _没有此 CSR 时，需要多条指令来计算 VLEN（以字节为单位），并且代码必须干扰当前的_ `vl` _和_ `vtype` _设置，这要求对它们进行保存和恢复。_

## 31.3.7. 向量起始索引（ **`vstart`** ）寄存器

_XLEN_ 位宽的可读写 `vstart` CSR 指定向量指令要执行的第一个元素的索引，如第 31.5.4 节所述。

通常，`vstart` 仅在向量指令发生陷阱时由硬件写入，`vstart` 值表示陷阱发生时处理到的元素（可以是同步异常或异步中断），在处理可恢复的陷阱后应从该位置恢复执行。

所有向量指令被定义为从 `vstart` CSR 中给出的元素编号开始执行，使目的向量中较早的元素保持不被改动，并在执行结束时将 `vstart` CSR 重置为零。

**评论：** _所有向量指令，包括_ `vset{i}vl{i}` _，都将_ `vstart` _CSR 重置为零。_

引发非法指令异常的向量指令不修改 `vstart`。

`vstart` CSR 被定义为仅具有足够的可写位来保存最大元素索引（最大 VLMAX 减一）。

**评论：** _最大向量长度由最大 LMUL 设置 (8) 和最小 SEW 设置 (8) 获得，因此 VLMAX_max = 8*VLEN/8 = VLEN。例如，对于 VLEN=256，_ `vstart`

**评论：** _建议实现在_ `vstart` _超出边界时陷入陷阱。不需要必须陷入陷阱，因为未来可能对_ `vstart` _高位用于存储不精确的陷阱信息。_

`vstart` CSR 可由非特权代码写入，但非零的 `vstart` 值可能导致向量指令在某些实现上运行显著变慢，因此应用程序员不应使用 `vstart`。少数向量指令不能在非零 `vstart` 值下执行，并将如下定义引发非法指令异常。

**评论：** _例如，某些实现在向量算术指令执行期间永远不会接受中断，而是等待指令完成后才接受中断。这类实现允许在尝试以非零_ `vstart` _执行向量算术指令时引发非法指令异常。_

## 31.3.11. 向量扩展在复位时的状态

向量扩展必须在复位时具有一致的状态。特别是，`vtype` 和 `vl` 必须具有可以被读取然后用单条 `vsetvl` 指令恢复的值。

**评论：** _建议在复位时，_ `vtype.vill` _被设置，_ `vtype` _中其余位为零，_ `vl` _设置为零。_

`vstart` 、 `vxrm` 、 `vxsat` CSR 在复位时可以有任意值。

**评论：** _大多数向量单元的使用将需要一个初始的_ `vset{i}vl{i}` _，这将重置_ `vstart` _。_ `vxrm` _和_ `vxsat` _字段应在软件使用前显式重置。_

向量寄存器在复位时可以有任意值。

## 31.5.1. 标量操作数

标量操作数可以是立即数，或取自 `x` 寄存器、 `f` 寄存器或向量寄存器的元素 0。标量结果写入 `x` 或 `f` 寄存器或向量寄存器的元素 0。任何向量寄存器都可用于保存标量，与当前 LMUL 设置无关。

**评论：** _Zfinx（"F in X"）是一个新的 ISA 扩展，其中浮点指令从整数寄存器文件中获取其参数。向量扩展也与 Zfinx 兼容，其中 Zfinx 向量扩展具有从_ `x` _寄存器获取其标量参数的向量-标量浮点指令。_

**评论：** _我们考虑过但未采用将_ `f` _寄存器覆盖在_ `v` _寄存器上。采用的方法减少了向量寄存器压力，避免了与标准调用约定的交互，简化了高性能标量浮点设计，并提供了与 Zfinx ISA 选项的兼容性。将_ `f` _与_ `v` _覆盖将提供在某些实现中降低状态位数量的优势，但会使高性能设计复杂化，并会阻止与 Zfinx ISA 选项的兼容。_

## 31.5.2. 向量操作数

每个向量操作数具有_有效元素宽度_（EEW）和_有效_ LMUL（EMUL），用于确定向量寄存器组内所有元素的大小和位置。默认情况下，对于大多数指令的大多数操作数，EEW=SEW 且 EMUL=LMUL。

某些向量指令具有相同元素数量但不同宽度的源和目的向量操作数，因此 EEW 和 EMUL 分别与 SEW 和 LMUL 不同，但 EEW/EMUL = SEW/LMUL。例如，大多数加宽算术指令具有 EEW=SEW 和 EMUL=LMUL 的源组，但具有 EEW=2*SEW 和 EMUL=2*LMUL 的目的组。窄化指令具有 EEW=2*SEW 和 EMUL=2*LMUL 的源操作数，但具有 EEW=SEW 和 EMUL=LMUL 的目的操作数。

The RISC-V Instruction Set Manual, Volume I | © RISC-V International

31.5. Vector Instruction Formats | Page 295

向量操作数或结果可能占用一个或多个向量寄存器，取决于 EMUL，但始终使用组中最低编号的向量寄存器指定。使用非最低编号的向量寄存器指定向量寄存器组是保留编码。

单个向量寄存器不能以多个 EEW 为单条指令提供源操作数。掩码寄存器源在此约束下被视为具有 EEW=1。导致同一向量寄存器以两个或多个不同 EEW 读取的编码（包括向量寄存器出现在两个或多个向量寄存器组中不同位置的情况）是保留的。

**评论：** _在实践中，在同一条指令中以不同 EEW 读取同一寄存器对软件没有好处，且此约束降低了内部依赖 EEW 重新排列数据的实现的复杂性。_

目的向量寄存器组可与源向量寄存器组重叠，仅当满足以下条件之一：

- 目的 EEW 等于源 EEW。
- 目的 EEW 小于源 EEW，且目的向量寄存器组中最低编号的寄存器与源向量寄存器组中最低编号的寄存器相同。（例如，当 LMUL=1 时，`vnsrl.wi v0, v0, 3` 是合法的，但目的为 `v1` 则不合法）。
- 目的 EEW 大于源 EEW，源 EMUL 至少为 1，且目的向量寄存器组中最高编号的寄存器与源向量寄存器组中最高编号的寄存器相同。（例如，当 LMUL=8 时，`vzext.vf4 v0, v6` 是合法的，但源为 `v0`、`v2` 或 `v4` 则不合法）。

为了确定寄存器组重叠约束，掩码元素的 EEW=1。

**评论：** _重叠约束旨在支持没有寄存器重命名的机器中的可恢复异常。_

任何违反重叠约束的指令编码是保留的。

当源和目的寄存器重叠且具有不同 EEW 时，指令是掩码未知和尾部未知的，与 `vtype` 中 `vta` 和 `vma` 位的设置无关。

指令使用的最大向量寄存器组不能大于 8 个向量寄存器（即 EMUL≤8），如果向量指令需要的向量寄存器组超过 8 个，则指令编码是保留的。例如，在 LMUL=8 时产生加宽向量寄存器组结果的加宽操作是保留的，因为这将意味着结果 EMUL=16。

加宽的标量值（例如，加宽归约操作的输入和输出）保存在向量寄存器的第一个元素中，且 EMUL=1。

## 31.5.3. 向量掩码

大多数向量指令都支持掩码。被掩码关闭（非活跃）的元素操作永远不会产生异常。被掩码关闭的元素对应的目的向量寄存器元素根据 `vtype` 中 `vma` 位的设置（第 31.3.4.3 节）采用掩码保留不变或掩码未知策略处理。

用于控制掩码向量指令执行的掩码值始终由向量寄存器 `v0` 提供。

**评论：** _掩码保存在向量寄存器中，而不是单独的掩码寄存器文件，以减少总架构状态并简化 ISA。_

**评论：** _未来的向量扩展可能提供更长的指令编码，带有完整的掩码寄存器说明符空间。_

掩码向量指令的目的向量寄存器组不能与源掩码寄存器（ `v0` ）重叠，除非目的向量寄存器正在被写入掩码值（例如比较）或归约的标量结果。这些指令编码是保留的。

**评论：** _此约束支持以非零_ `vstart` _值重新启动。_

其他向量寄存器可用于保存工作掩码值，并提供掩码向量逻辑操作来执行谓词计算。

如第 31.3.4.3 节所述，掩码目的尾部元素始终被视为尾部未知，与 `vta` 的设置无关。

## 31.5.3.1. 掩码编码

在可用时，掩码编码在指令的单比特 `vm` 字段中（ `inst[25]` ）。

|vm|描述|
|---|---|
|0|向量结果，仅在 v0.mask[i] = 1 处|
|1|无掩码|

向量掩码在汇编代码中表示为另一个向量操作数，使用 `.t` 指示当 `v0.mask[i]` 为 `1` 时操作发生（ `t` 表示 "true"）。如果未指定掩码操作数，则假定为无掩码向量执行（ `vm=1` ）。

```
    vop.v*    v1, v2, v3, v0.t  # 在 v0.mask[i]=1 处启用, vm=0
    vop.v*    v1, v2, v3        # 无掩码向量操作, vm=1
```

**评论：** _尽管当前向量扩展仅支持一个向量掩码寄存器_ `v0` _且仅支持真谓词形式，汇编语法将其完整写出以兼容未来可能添加掩码寄存器说明符并支持真和补掩码值的扩展。掩码操作数上的_ `.t` _后缀也有助于视觉上编码掩码的使用。_

**评论：** _`.mask` 后缀不是汇编语法的一部分。我们仅在下标掩码向量的上下文中附加它，例如_ `v0.mask[i]` _。_

## 31.5.4. 预启动、活跃、非活跃、体和尾部元素定义

向量指令执行期间操作的目的元素索引可分为三个不相交的子集。

- _预启动_元素是其元素索引小于 `vstart` 寄存器中初始值的元素。预启动元素不引发异常，也不更新目的向量寄存器。

The RISC-V Instruction Set Manual, Volume I | © RISC-V International

- _体_元素是其元素索引大于或等于 `vstart` 寄存器中的初始值，且小于 `vl` 中当前向量长度设置的元素。体可进一步分为两个不相交的子集：

  - _活跃_元素是向量指令执行期间在体内且当前掩码在该元素位置处启用的元素。活跃元素可以引发异常并更新目的向量寄存器组。

  - _非活跃_元素是在体内但当前掩码在该元素位置处禁用的元素。非活跃元素不引发异常，且不更新任何目的向量寄存器组，除非指定了掩码未知（ `vtype.vma` =1），在这种情况下非活跃元素可能被覆写为 1。

- _尾部_元素是向量指令执行期间超过 `vl` 中指定的当前向量长度设置的元素。尾部元素不引发异常，且不更新任何目的向量寄存器组，除非指定了尾部未知（ `vtype.vta` =1），在这种情况下尾部元素可能被覆写为 1，或对于掩码产生指令（掩码加载除外）被覆写为指令的结果。当 LMUL < 1 时，尾部包括同一向量寄存器中超过 VLMAX 的元素。

```
    for element index x
    prestart(x) = (0 <= x < vstart)
    body(x)     = (vstart <= x < vl)
    tail(x)     = (vl <= x < max(VLMAX,VLEN/SEW))
    mask(x)     = unmasked || v0.mask[x] == 1
    active(x)   = body(x) && mask(x)
    inactive(x) = body(x) && !mask(x)
```

当 `vstart` ≥ `vl` 时，没有体元素，且没有元素在任何目的向量寄存器组中被更新，包括没有尾部元素被更新为未知值。

**评论：** _因此，当_ `vl` _=0 时，不论_ `vstart` _为何值，目的向量寄存器组中没有元素（包括未知元素）被更新。_

写入 `x` 寄存器或 `f` 寄存器的指令即使在 `vstart` ≥ `vl` （包括 `vl` =0）时也会执行写入。

**评论：** _某些指令，如_ `vslidedown` _和_ `vrgather` _可能读取超过_ `vl` _甚至 VLMAX 的源向量寄存器组中的索引。一般策略是当索引大于源向量寄存器组中的 VLMAX 时返回值 0。_

## 31.6.1.1. 不受支持的 **`vtype`** 值

如果 `vtype` 值不受实现支持，则在 `vtype` 中设置 `vill` 位，`vtype` 中的其余位设为零，且 `vl` 寄存器也设为零。

**评论：** _早期草案要求在将_ `vtype` _设置为非法值时陷入陷阱。然而，这将向 ISA 添加第一个对 CSR 写入的数据依赖陷阱。实现可以选择在写入非法值时陷阱，以支持新配置的前向兼容性。当前方案支持设置_ `vill` _而非陷阱，以允许仿真通过在给定设置下检查_ `vill` _是否清零来加权运行时查询支持的向量单元配置。_

设置了 `vill` 的 `vtype` 值被视为不受支持的配置。

实现必须考虑 `vtype` 值的所有位来确定配置是否受支持。`vtype` 值中任何位置的不受支持值必须导致 `vill` 被设置。

**评论：** _特别地，必须检查_ `vsetvl` _指令的寄存器_ `vtype` _参数的所有 XLEN 位。实现不能忽略它们未实现的字段。必须检查所有位，以确保假设_ `vtype` _中不受支持的向量特性的新代码会在旧实现上陷入陷阱，而不是错误地执行。_

当 _rs1_ 不为 `x0` 时，AVL 是由 _rs1_ 指定的 `x` 寄存器中保存的无符号整数，新的 `vl` 值也写入由 _rd_ 指定的 `x` 寄存器。

当 _rs1_ = `x0` 但 _rd_ ≠ `x0` 时，最大无符号整数值（ `~0` ）用作 AVL，结果 VLMAX 写入 `vl` 以及由 `rd` 指定的 `x` 寄存器。

当 _rs1_ = `x0` 且 _rd_ = `x0` 时，指令操作如同将 `vl` 中的当前向量长度用作 AVL，结果值写入 `vl`，但不写入目的寄存器。此形式仅在 VLMAX 和因此 `vl` 实际上不会被新的 SEW/LMUL 比率更改时才可使用。使用会导致 VLMAX 更改的新的 SEW/LMUL 比率的指令是保留的。如果之前 `vill` 为 1，指令的使用也是保留的。实现可以在任一情况下设置 `vill`。

**评论：** _指令的最后一种形式允许在保持当前_ `vl` _的同时更改_ `vtype` _寄存器，前提是 VLMAX 不减少。此设计旨在确保_ `vl` _始终为当前_ `vtype` _设置保存合法值。当前_ `vl` _值可以从_ `vl` _CSR 读取。如果新的 SEW/LMUL 比率导致 VLMAX 缩小，这些指令可能会减少_ `vl` _值，因此这种情况被保留，因为不清楚这是否是一个普遍有用的操作，且实现可以通过这些指令假定_ `vl` _不加更改以优化其微架构。_

对于 `vsetivli` 指令，AVL 编码为 `rs1` 字段中的 5 位零扩展立即数（0—31）。

**评论：** _`vsetivli` 的 AVL 编码与常规 CSR 立即数值相同。_

**评论：** _`vsetivli` 指令在向量维度较小且已知适合向量寄存器时提供更紧凑的代码，此时没有条带挖掘开销。_

## 31.6.3. 设置 **`vl`** 的约束

`vset{i}vl{i}` 指令首先根据其 `vtype` 参数设置 VLMAX，然后设置 `vl` 遵守以下约束：

1. `vl = AVL` 若 `AVL ≤ VLMAX`
2. `ceil(AVL / 2) ≤ vl ≤ VLMAX` 若 `AVL < (2 * VLMAX)`
3. `vl = VLMAX` 若 `AVL ≥ (2 * VLMAX)`
4. 对于相同的输入 AVL 和 VLMAX 值，在任何给定实现上是确定性的
5. 以下特定属性来自前述规则：

   - a. `vl = 0` 若 `AVL = 0`
   - b. `vl > 0` 若 `AVL > 0`
   - c. `vl ≤ VLMAX`
   - d. `vl ≤ AVL`
   - e. 从 `vl` 读取的值当用作 `vset{i}vl{i}` 的 AVL 参数时，若结果 VLMAX 等于读取 `vl` 时的 VLMAX 值，则结果 `vl` 值相同

**评论：** _`vl` 设置规则被设计得足够严格，以在寄存器溢出和上下文切换中保留_ `vl` _行为（对于_ `AVL ≤ VLMAX` _），同时又足够灵活，使实现能够在_ `AVL > VLMAX` _时改善向量通道利用率。_

**评论：** _例如，这允许实现在_ `VLMAX < AVL < 2*VLMAX` _时设置_ `vl = ceil(AVL / 2)` _，以便在条带挖掘循环的最后两次迭代中均匀分配工作。_

**评论：** _要求 2 确保归约循环的第一次条带挖掘迭代使用所有迭代中最大的向量长度，即使在_ `AVL < 2*VLMAX` _的情况下也是如此。这允许软件避免需要显式计算条带挖掘循环中观察到的向量长度的运行最大值。要求 2 还允许实现在_ `VLMAX < AVL < 2*VLMAX` _时设置 vl 为 VLMAX。_

SEW 和 LMUL 设置可以动态更改，以在单个循环中为混合宽度操作提供高吞吐量。

```

# 入口处:
#  a0 保存要处理的总元素数
#  a1 保存源数组的地址
#  a2 保存目的数组的地址
loop:
    vsetvli a3, a0, e16, m4, ta, ma  # vtype = 16 位整数向量;
                                      # 同时用 vl 更新 a3（本次迭代的元素数）
    vle16.v v4, (a1)        # 获取 16b 向量
    slli t1, a3, 1          # 将本次迭代的元素数乘以 2 字节/源元素
    add a1, a1, t1          # 移动指针
    vwmul.vx v8, v4, x10    # 加宽乘到 32b 存入 <v8--v15>
    vsetvli x0, x0, e32, m8, ta, ma  # 操作 32b 值
    vsrl.vi v8, v8, 3

    slli t1, a3, 2          # 将本次迭代的元素数乘以 4 字节/目的元素
    add a2, a2, t1          # 移动指针
    sub a0, a0, a3          # 按 vl 递减计数
    bnez a0, loop           # 还有更多？
```

## 31.7.2. 向量加载/存储寻址模式

向量扩展支持 unit-stride、constant-stride 和索引（scatter/gather）寻址模式。向量加载/存储基址寄存器和步长取自 GPR `x` 寄存器。

所有向量访问的基有效地址由 `rs1` 中命名的 `x` 寄存器的内容给出。

向量 unit-stride 操作访问从基有效地址开始连续存储在内存中的元素。

向量 constant-stride 操作在基有效地址处访问第一个内存元素，然后按 `rs2` 指定的 `x` 寄存器中包含的字节偏移量在后续地址增量处访问后续元素。

向量索引操作将 `vs2` 指定的向量偏移操作数的每个元素的内容加到基有效地址上，以给出每个元素的有效地址。数据向量寄存器组的 EEW=SEW，EMUL=LMUL，而偏移向量寄存器组的 EEW 在指令中编码，EMUL=(EEW/SEW)*LMUL。

向量偏移操作数被视为字节地址偏移的向量。

**评论：** _索引操作也可用于访问对象向量中的字段，其中_ `vs2` _向量保存指向对象基址的指针，标量_ `x` _寄存器保存成员字段的偏移量。支持这种情况是为什么索引操作未定义为按数据 EEW 缩放元素索引的原因。_

如果向量偏移元素比 XLEN 窄，则在加到基有效地址之前将其零扩展到 XLEN。如果向量偏移元素比 XLEN 宽，则将最低有效 XLEN 位用于地址计算。

如果实现不支持偏移元素的 EEW，则指令是保留的。

**评论：** _配置文件可能对最大支持的索引 EEW 设置一个上限（例如仅到 XLEN），小于 ELEN。_

## 31.7.7. Unit-Stride 仅首故障加载

unit-stride 仅首故障加载指令用于向量化具有数据依赖退出条件的循环（"while" 循环）。这些指令作为常规加载执行，不同之处在于它们仅在元素 0 处因同步异常而陷入陷阱。如果元素 0 引发异常，`vl` 不修改，且陷阱被接受。如果元素 > 0 引发异常，相应的陷阱不被接受，且向量长度 `vl` 被缩减为会引发异常的元素的索引。

加载指令可能覆写超过陷阱报告的元素索引之外的目的向量寄存器组中的活跃元素。类似地，仅首故障加载指令可能更新超过导致向量长度裁剪的元素之外的目的活跃元素（但不超过原始向量长度）。这些虚假更新的值不必对应所寻址内存位置的内存值。非幂等内存位置仅在已知相应的元素加载操作不会因陷阱或向量长度裁剪而重新启动时才可被访问。

`vstart` 值以整个段为单位。如果在访问段期间发生陷阱，则对于故障段的部分访问是否在陷阱接受之前执行是由实现定义的。

## 31.7.8.1. 向量 Unit-Stride 段加载和存储

向量 unit-stride 加载和存储段指令将打包的连续段移入多个目的向量寄存器组。

## 31.8. 向量内存对齐约束

如果向量内存指令访问的元素未自然对齐到元素大小，则该元素要么成功传输，要么在该元素上引发地址未对齐异常。

对未对齐向量内存访问的支持与实现对标量未对齐内存访问的支持无关。

**评论：** _实现可以分别对标量和向量内存访问提供硬件支持的某些或全部未对齐访问，也可以都不提供。应定义一个单独的 PMA 来确定在相关地址范围内是否支持向量未对齐访问。_

向量未对齐内存访问遵循与标量未对齐内存访问相同的原子性规则。

## 31.9. 向量内存一致性模型

向量内存指令在本地 hart 上按程序顺序执行。

向量内存指令在指令级别遵循 RVWMO。如果实现了 Ztso 扩展，向量内存指令还在指令级别遵循 RVTSO。

除了向量有序索引加载和存储外，指令内的元素操作是无序的。

向量有序索引加载和存储分别按元素顺序从内存读取和写入元素，在元素级别遵守 RVWMO。

**评论：** _Ztso 仅在指令级别施加 RVTSO；指令内排序遵循 RVWMO，无论是否实现了 Ztso。_

**评论：** _需要更正式的定义。_

受向量长度寄存器 `vl` 影响的指令对 `vl` 具有控制依赖而非数据依赖。

向量-向量操作分别从 `vs2` 和 `vs1` 指定的向量寄存器组中获取两个操作数向量。

向量-标量操作可以具有三种可能的形式。在所有三种形式中，向量寄存器组操作数由 `vs2` 指定。第二个标量源操作数来自以下三种替代来源之一：

1. 对于整数操作，标量可以是 5 位立即数 `imm[4:0]`，编码在 `rs1` 字段中。除非另有规定，该值符号扩展到 SEW 位。

2. 对于整数操作，标量可以从 `rs1` 指定的标量 `x` 寄存器获取。如果 XLEN>SEW，使用 `x` 寄存器的最低有效 SEW 位，除非另有规定。如果 XLEN<SEW，来自 `x` 寄存器的值符号扩展到 SEW 位。

3. 对于浮点操作，标量可以从标量 `f` 寄存器获取。如果 FLEN > SEW，检查 `f` 寄存器中的值是否为有效的 NaN-boxed 值，在这种情况下使用 `f` 寄存器的最低有效 SEW 位，否则使用规范 NaN 值。任何浮点向量操作数的 EEW 不是支持的浮点类型宽度（包括当 FLEN < SEW 时）的向量指令是保留的。

**评论：** _某些指令将 5 位立即数零扩展，并通过在汇编语法中命名立即数为_ `uimm` _来表示这一点。_

**评论：** _当向 Zfinx/Zdinx/Zhinx 扩展添加向量扩展时，浮点标量参数取自_ `x` _寄存器。NaN-boxing 在这些扩展中不受支持，因此比 XLEN 窄的操作数不检查 NaN box；位 XLEN-1:EEW 被忽略。对于 RV32_Zdinx，EEW=64 标量参数由_ `x` _寄存器对提供。_

## 31.11.3. 向量整数扩展

向量整数扩展指令将具有小于 SEW 的 EEW 的源向量整数操作数零扩展或符号扩展，以填充目的中的 SEW 大小元素。源的 EEW 是 SEW 的 1/2、1/4 或 1/8，而源的 EMUL 是 (EEW/SEW)*LMUL。目的的 EEW 等于 SEW，EMUL 等于 LMUL。

```
vzext.vf2 vd, vs2, vm  # 零扩展 SEW/2 源到 SEW 目的
vsext.vf2 vd, vs2, vm  # 符号扩展 SEW/2 源到 SEW 目的
vzext.vf4 vd, vs2, vm  # 零扩展 SEW/4 源到 SEW 目的
vsext.vf4 vd, vs2, vm  # 符号扩展 SEW/4 源到 SEW 目的
vzext.vf8 vd, vs2, vm  # 零扩展 SEW/8 源到 SEW 目的
vsext.vf8 vd, vs2, vm  # 符号扩展 SEW/8 源到 SEW 目的
```

如果源 EEW 不是支持的宽度，或源 EMUL 将低于最小合法 LMUL，则指令编码是保留的。

**评论：** _标准向量加载指令访问与目的寄存器元素大小相同的内存值。某些应用程序代码需要在更宽的元素中操作一定范围的操作数宽度，例如，从内存加载一个字节并加到八字元素中。为避免必须提供向量加载指令数量与数据类型数量（字节、字、半字以及有符号/无符号变体）的叉积，我们改为添加显式扩展指令，如果没有合适的加宽算术指令可用，可以使用这些扩展指令。_

## 31.11.4. 向量整数进位加/借位减指令

为了支持多字整数算术，提供了操作进位位的指令。对于每个操作（加法或减法），提供了两条指令：一条提供结果（SEW 宽度），第二条生成进位输出（编码为掩码布尔值的单个位）。

进位输入和输出使用第 31.4.5 节所述的掩码寄存器布局表示。由于编码约束，进位输入必须来自隐式的 `v0` 寄存器，但进位输出可以写入任何遵守源/目的重叠限制的向量寄存器。

`vadc` 和 `vsbc` 将源操作数和进位输入或借位输入相加或相减，并将结果写入向量寄存器 `vd`。这些指令被编码为掩码指令（ `vm=0` ），但它们操作并写回所有体元素。对应于无掩码版本（ `vm=1` ）的编码是保留的。

`vmadc` 和 `vmsbc` 将源操作数相加或相减，如果掩码（ `vm=0` ）则可选地加上进位输入或减去借位输入，并将结果进位输出或借位输出写回掩码寄存器 `vd`。如果无掩码（ `vm=1` ），则没有进位输入或借位输入。这些指令操作并写回所有体元素，即使被掩码也是如此。因为这些指令产生掩码值，它们始终以尾部未知策略操作。

## 31.11.15. 向量整数合并指令

向量整数合并指令基于掩码组合两个源操作数。与常规算术指令不同，合并操作所有体元素（即从 `vstart` 到 `vl` 中当前向量长度的元素集合）。

`vmerge` 指令编码为掩码指令（ `vm=0` ）。指令按如下方式组合两个源。在掩码值为零的元素处，第一个操作数复制到目的元素，否则第二个操作数复制到目的元素。第一个操作数始终是由 `vs2` 指定的向量寄存器组。第二个操作数是由 `vs1` 指定的向量寄存器组或由 `rs1` 指定的标量 `x` 寄存器，或 5 位符号扩展立即数。

```
vmerge.vvm vd, vs2, vs1, v0  # vd[i] = v0.mask[i] ? vs1[i] : vs2[i]
vmerge.vxm vd, vs2, rs1, v0  # vd[i] = v0.mask[i] ? x[rs1] : vs2[i]
vmerge.vim vd, vs2, imm, v0  # vd[i] = v0.mask[i] ? imm    : vs2[i]
```

## 31.11.16. 向量整数移动指令

向量整数移动指令将源操作数复制到向量寄存器组。`vmv.v.v` 变体复制向量寄存器组，而 `vmv.v.x` 和 `vmv.v.i` 变体将标量寄存器或立即数_散播_到目的向量寄存器组的所有活跃元素。这些指令编码为无掩码指令（ `vm=1` ）。第一个操作数说明符（ `vs2` ）必须包含 `v0`，`vs2` 中的任何其他向量寄存器编号是_保留_的。

```
vmv.v.v vd, vs1 # vd[i] = vs1[i]
vmv.v.x vd, rs1 # vd[i] = x[rs1]
vmv.v.i vd, imm # vd[i] = imm
```

**评论：** _掩码值可以使用序列_ `vmv.v.i vd, 0; vmerge.vim vd, vd, 1, v0` _加宽为 SEW 宽度元素。_

**评论：** _向量整数移动指令与向量合并指令共享编码，但使用_ `vm=1` _和_ `vs2=v0` _。_

形式 `vmv.v.v vd, vd`（保持体元素不变）可用于指示寄存器接下来将以等于 SEW 的 EEW 使用。

**评论：** _在内部根据 EEW 重新组织数据的实现可以根据 SEW 混洗内部表示。不在内部重新组织数据的实现可以动态省略此指令（除了将_ `vstart` _重置为 0 外）。_

**评论：** _`vmv.v.v vd, vd` 指令不是 RISC-V HINT，因为尾部未知设置可能在某些实现上引起架构状态更改。_

## 31.12. 向量定点算术指令

前述整数算术指令集被扩展以支持定点算术。

定点数是两者补码的有符号或无符号整数，被解释为具有隐式分母的分数中的分子。定点指令旨在应用于分子；软件负责管理分母。一个 N 位元素可以保存范围 -2[N-1] …+2[N-1]-1 的两者补码有符号整数，以及范围 0 … +2[N]-1 的无符号整数。定点指令通过支持缩放和舍入来帮助保持窄操作数的精度，并可以通过将结果饱和到目的格式范围来处理溢出。

## 31.12.3. 向量单倍宽度分数乘法（带舍入和饱和）

有符号分数乘法指令产生两个 SEW 输入的 2*SEW 积，然后将结果右移 SEW-1 位，根据 `vxrm` 舍入这些位，然后将结果饱和以适应 SEW 位。如果结果导致饱和，则设置 `vxsat` 位。

```
# 有符号饱和舍入分数乘法
# 关于舍入计算请参见 vxrm 描述

```

```
vsmul.vx vd, vs2, rs1, vm  # vd[i] = clip(roundoff_signed(vs2[i]*x[rs1], SEW-1))
```

**评论：** _当两个 N 位有符号数相乘时，最大量级由 -2[N-1] * -2[N-1] 获得，产生结果 +2[2N-2]，当保存在 2N 位中时具有单个（零）符号位。所有其他乘积在 2N 位中具有两个符号位。为了在 N 结果位中保留更高的精度，乘积右移比 N 少一位，对最大量级结果进行饱和，但将所有其他乘积的结果精度提高一位。_

**评论：** _我们不提供其中一个输入为无符号的等效分数乘法，因为这些将保留所有高 SEW 位且不需要饱和。此操作在舍入仅是截断（_ `rdn` _）的情况下部分由_ `vmulhu` _和_ `vmulhsu` _指令覆盖。_

## 31.12.5. 向量窄化定点裁剪指令

`vnclip` 指令用于将定点值打包到较窄的目的中。指令支持舍入、缩放和饱和到最终目的格式。源数据在 `vs2` 指定的向量寄存器组中。缩放移位量值可以来自向量寄存器组 `vs1`、标量整数寄存器 `rs1` 或零扩展的 5 位立即数。向量或标量移位量值的低 lg2(2*SEW) 位（例如，对于 SEW=64 位到 SEW=32 位的窄化操作，使用低 6 位）用于控制右移量，这提供缩放。

```
# 窄化无符号裁剪
#                                SEW                            2*SEW   SEW
vnclipu.wv vd, vs2, vs1, vm  # vd[i] = clip(roundoff_unsigned(vs2[i], vs1[i]))
vnclipu.wx vd, vs2, rs1, vm  # vd[i] = clip(roundoff_unsigned(vs2[i], x[rs1]))
vnclipu.wi vd, vs2, uimm, vm # vd[i] = clip(roundoff_unsigned(vs2[i], uimm))
```

```
# 窄化有符号裁剪
vnclip.wv vd, vs2, vs1, vm   # vd[i] = clip(roundoff_signed(vs2[i], vs1[i]))
vnclip.wx vd, vs2, rs1, vm   # vd[i] = clip(roundoff_signed(vs2[i], x[rs1]))
vnclip.wi vd, vs2, uimm, vm  # vd[i] = clip(roundoff_signed(vs2[i], uimm))
```

对于 `vnclipu` / `vnclip`，舍入模式在 `vxrm` CSR 中指定。舍入发生在目的的最低有效位附近，在饱和之前。

对于 `vnclipu`，移位舍入的源值被视为无符号整数，如果结果会溢出被视为无符号整数的目的则饱和。

**评论：** _没有单条指令可以将有符号值饱和到无符号目的。如果不需要为负数设置_ `vxsat` _值，可以使用对 0 执行_ `vmax` _来移除负数的两条向量指令序列，然后使用_ `vnclipu` _将结果无符号值裁剪到目的。在这两条指令之间需要_ `vsetvli` _来更改 SEW。_

对于 `vnclip`，移位舍入的源值被视为有符号整数，如果结果会溢出被视为有符号整数的目的则饱和。

如果任何目的元素被饱和，则在 `vxsat` 寄存器中设置 `vxsat` 位。

## 31.13. 向量浮点指令

标准向量浮点指令将元素视为 IEEE-754/2008 兼容值。如果向量浮点操作数的 EEW 不对应于支持的 IEEE 浮点类型，则指令编码是保留的。

**评论：** _是否支持浮点，以及支持哪些元素宽度，由特定的向量扩展决定。当前扩展集包括对 32 位和 64 位浮点值的支持。当添加 16 位和 128 位元素宽度时，它们也将被视为 IEEE-754/2008 兼容值。未来扩展中可能支持其他浮点格式。_

向量浮点指令需要存在与支持的向量浮点元素宽度对应的基本标量浮点扩展。

**评论：** _特别是，未来支持 16 位半精度浮点值的向量扩展也需要一些标量半精度浮点支持。_

如果浮点单元状态字段 `mstatus.FS` 为 `Off`，则任何尝试执行向量浮点指令将引发非法指令异常。任何修改任何浮点扩展状态（即浮点 CSR 或 `f` 寄存器）的向量浮点指令必须将 `mstatus.FS` 设置为 `Dirty`。

如果实现了 hypervisor 扩展且 V=1，则 `vsstatus.FS` 字段对向量浮点指令额外生效。如果 `vsstatus.FS` 或 `mstatus.FS` 为 `Off`，则任何尝试执行向量浮点指令将引发非法指令异常。任何修改任何浮点扩展状态（即浮点 CSR 或 `f` 寄存器）的向量浮点指令必须将 `mstatus.FS` 和 `vsstatus.FS` 都设置为 `Dirty`。

向量浮点指令关于 NaN 的行为与标量浮点指令相同。

浮点向量-标量操作的标量值按第 31.10.1 节所述获取。

## 31.13.10. 向量浮点倒数估计指令
