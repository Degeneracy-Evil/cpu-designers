# RISC-V PLIC 开发参考手册

> 基于 RISC-V Platform-Level Interrupt Controller Specification v1.0.0 (2023-03, 已批准)

---

## 1. 概述

PLIC（平台级中断控制器）将各设备中断多路复用到 Hart 上下文的外部中断线上，并提供硬件中断优先级支持。

| 参数 | 最大值 | 说明 |
|------|--------|------|
| 中断源数量 | 1023 | ID 0 保留（表示"无中断"），有效 ID 范围 1~1023 |
| 上下文数量 | 15872 | 实际数量取决于实现 |
| 寄存器宽度 | 32 位 | 使用 LW/SW 指令原子访问 |

---

## 2. 核心概念

### 2.1 中断目标与 Hart 上下文

- **中断目标**通常是 Hart 上下文，即某个 Hart 上的某个特权模式（M 模式 / S 模式）
- 中断通知出现在 `mip/sip` 寄存器的 `meip/seip` 位
- 通知仅在对应特权模式已委派外部中断时才出现在低特权级 `xip` 寄存器中
- **PLIC 不支持中断嵌套/抢占**，需由核心侧自行处理
- PLIC 支持中断**多播**：所有使能的目标都会收到同一活跃中断的通知

### 2.2 中断网关（Interrupt Gateway）

- 将全局中断信号转换为统一的中断请求格式
- 每个中断源在 PLIC 核心中**最多只能有一个挂起请求**（对应 IP 位置位）
- **电平触发**：首次断言产生请求，此后不再转发新请求，直到收到完成消息；若完成时中断仍断言，则再次转发
- **边沿触发**：首次匹配边沿产生请求，后续边沿可选忽略或计数；须收到完成消息后才转发下一个请求
- **MSI**：经系统互连发送消息包，解码后选择对应网关，按边沿触发方式处理

### 2.3 中断标识符（Interrupt ID）

- 全局中断源分配从 **1** 开始的无符号整数 ID
- **ID 0 保留**，表示"无中断"
- 相同优先级时，**较小 ID 优先级更高**（用于打破平局）

### 2.4 中断处理流程

```
全局中断源 ──→ 中断网关 ──→ PLIC 核心(IP位) ──→ 中断通知 ──→ 目标Hart
                                                          │
                     中断完成消息 ←── 中断处理完成 ←── Claim请求(获取最高优先级中断ID)
                          │
                     网关可转发下一个同源中断
```

1. 全局中断源发送信号到中断网关
2. 网关发送单个中断请求到 PLIC 核心，锁存到 IP 位
3. PLIC 核心向使能且优先级超过阈值的目标转发中断通知
4. 目标响应外部中断，发送 **Claim** 请求获取最高优先级挂起中断的 ID
5. PLIC 核心清除对应 IP 位并返回中断 ID
6. 目标服务完毕后，向网关发送**中断完成**消息
7. 网关此后可转发同源的下一个中断请求

## 3. 内存映射

PLIC 基地址由平台实现决定。所有寄存器为 32 位宽，使用 LW/SW 原子访问。

### 3.1 总体内存布局

| 偏移地址 | 内容 |
|----------|------|
| `0x000000` ~ `0x000FFC` | 中断源优先级（1~1023），0 号保留 |
| `0x001000` ~ `0x00107C` | 中断挂起位（32 个 32 位寄存器） |
| `0x002000` ~ `0x1F1FFC` | 中断使能位（15872 个上下文） |
| `0x1F2000` ~ `0x1FFFFC` | 保留 |
| `0x200000` ~ `0x3FFFFFC` | 优先级阈值 + Claim/Complete（15872 个上下文） |

### 3.2 详细偏移地址

#### 中断源优先级

| 偏移 | 说明 |
|------|------|
| `0x000000` | 保留（中断源 0 不存在） |
| `0x000004` | 中断源 1 优先级 |
| `0x000008` | 中断源 2 优先级 |
| ... | ... |
| `0x000FFC` | 中断源 1023 优先级 |

> 块大小：1024 × 4 = 4096 (0x1000) 字节

#### 中断挂起位

| 偏移 | 说明 |
|------|------|
| `0x001000` | 中断源 #0 ~ #31 挂起位 |
| `0x001004` | 中断源 #32 ~ #63 挂起位 |
| ... | ... |
| `0x00107C` | 中断源 #992 ~ #1023 挂起位 |

> 块大小：1024 / 8 = 128 (0x80) 字节，每位对应一个中断源

#### 中断使能位

每个上下文占 32 个 32 位寄存器（128 字节），上下文间偏移 0x80。

| 偏移 | 说明 |
|------|------|
| `0x002000` | 上下文 0，中断源 #0 ~ #31 使能 |
| `0x002004` | 上下文 0，中断源 #32 ~ #63 使能 |
| ... | ... |
| `0x00207C` | 上下文 0，中断源 #992 ~ #1023 使能 |
| `0x002080` | 上下文 1，中断源 #0 ~ #31 使能 |
| ... | ... |
| `0x1F1F80` | 上下文 15871，中断源 #0 ~ #31 使能 |
| `0x1F1FFC` | 上下文 15871，中断源 #992 ~ #1023 使能 |

> 块大小：(1024/8) × 15872 = 2,031,616 (0x1F0000) 字节

#### 优先级阈值与 Claim/Complete

每个上下文占 4K (0x1000) 字节对齐的空间，其中偏移 +0 为阈值，+4 为 Claim/Complete。

| 偏移 | 说明 |
|------|------|
| `0x200000` | 上下文 0 优先级阈值 |
| `0x200004` | 上下文 0 Claim/Complete |
| `0x201000` | 上下文 1 优先级阈值 |
| `0x201004` | 上下文 1 Claim/Complete |
| `0x202000` | 上下文 2 优先级阈值 |
| `0x202004` | 上下文 2 Claim/Complete |
| ... | ... |
| `0x3FFF000` | 上下文 15871 优先级阈值 |
| `0x3FFF004` | 上下文 15871 Claim/Complete |

> 块大小：4096 × 15872 = 65,011,712 (0x3E00000) 字节

## 4. 中断优先级

- 优先级为无符号小整数，最大级别由平台实现决定
- **优先级 0**：保留，表示"永不中断"（等效禁用）
- **优先级 1**：最低有效优先级
- 优先级值越大，优先级越高
- 相同优先级时，**较小中断 ID 优先级更高**
- 优先级寄存器为 **WARL** 字段，实现可硬接线所有优先级

### 寄存器访问

- 基地址：PLIC base + `0x000000`
- 每个中断源一个 32 位寄存器，偏移 = 中断源 ID × 4

---

## 5. 中断挂起位

- 以 32 位寄存器数组组织，中断 ID N 的挂起位位于第 (N/32) 个字的第 (N mod 32) 位
- 位 0（字 0 的 bit 0）硬接线为 0（中断源 0 不存在）
- **清除挂起位**：使能对应中断后执行 Claim 操作

### 寄存器访问

- 基地址：PLIC base + `0x001000`

---

## 6. 中断使能

- 以 32 位寄存器数组组织，打包方式与挂起位相同
- 位 0（字 0 的 bit 0）硬接线为 0（中断源 0 不存在）
- 每个上下文有独立的使能寄存器组
- PLIC 如何为上下文（Hart + 特权模式）组织中断**超出本规范范围**，须由厂商规范定义

### 寄存器访问

- 基地址：PLIC base + `0x002000`
- 上下文 N 的使能基偏移 = `0x002000 + N × 0x80`

---

## 7. 优先级阈值

- 每个上下文有一个阈值寄存器（WARL 字段）
- PLIC 将屏蔽所有优先级 **≤ 阈值** 的中断
- **阈值 0**：允许所有非零优先级中断
- 设置阈值为最大值可禁用中断通知（轮询模式）

### 寄存器访问

- 上下文 N 的阈值偏移 = `0x200000 + N × 0x1000`

---

## 8. 中断声明（Claim）

- 目标通过**读取** Claim/Complete 寄存器执行 Claim
- PLIC 原子地返回该目标最高优先级挂起中断的 ID，并清除对应 IP 位
- 无挂起中断时返回 **0**
- Claim 后若有更低优先级挂起中断，EIP 可能不会清除
- **Claim 不受优先级阈值影响**，可在任何时候执行
- 即使 EIP 未置位，执行 Claim 也是合法的

### 寄存器访问

- 上下文 N 的 Claim 偏移 = `0x200000 + N × 0x1000 + 4`
- 操作：**读**该寄存器

---

## 9. 中断完成（Complete）

- 通过**写入**中断 ID 到 Claim/Complete 寄存器发送完成消息
- PLIC **不检查**完成 ID 是否与上次 Claim ID 匹配
- 若完成 ID 对应的中断源未对当前目标使能，完成消息被**静默忽略**
- 完成后网关才能转发同源的下一个中断请求

### 寄存器访问

- 上下文 N 的 Complete 偏移 = `0x200000 + N × 0x1000 + 4`（与 Claim 寄存器地址相同）
- 操作：**写**中断 ID 到该寄存器

---

## 10. 快速参考：上下文 N 寄存器偏移公式

| 寄存器 | 偏移公式 | 操作 |
|--------|----------|------|
| 中断源 S 优先级 | `0x000000 + S × 4` | 读/写 |
| 中断源 S 挂起位 | `0x001000 + (S/32) × 4` 的第 `(S%32)` 位 | 只读 |
| 中断源 S 使能（上下文 N） | `0x002000 + N × 0x80 + (S/32) × 4` 的第 `(S%32)` 位 | 读/写 |
| 优先级阈值（上下文 N） | `0x200000 + N × 0x1000` | 读/写 |
| Claim / Complete（上下文 N） | `0x200000 + N × 0x1000 + 4` | 读=Claim，写=Complete |

---

## 11. 典型中断处理代码流程

```c
// 1. Claim：获取最高优先级挂起中断 ID
uint32_t id = *(volatile uint32_t *)(PLIC_BASE + 0x200004 + context * 0x1000);

if (id != 0) {
    // 2. 服务中断
    handle_interrupt(id);

    // 3. Complete：通知 PLIC 中断处理完成
    *(volatile uint32_t *)(PLIC_BASE + 0x200004 + context * 0x1000) = id;
}
```
