## 发现的问题

### 问题 1: OpenSBI 遭遇 83 次非法指令异常 (mcause=2)

**严重程度**: 高  
**状态**: 已确认  

trap_trace.log 记录了 84 个 trap 条目:
- 1 个 mcause=0 (初始 reset trap, mepc=0x00000000)
- **83 个 mcause=2 (非法指令 illegal instruction)**

所有非法指令发生在 PC=0x800031e4 ~ 0x800050ec 范围内（OpenSBI 早期代码段）。  
trap handler 位于 0x80000a40，每次 trap 后 mepc+4 跳过非法指令并返回。

**可能原因**:
- CPU 不支持 OpenSBI 使用的某些指令（如 CSR 指令、原子指令、浮点指令等）
- 指令解码器存在 bug，将合法指令误判为非法
- 某些扩展未启用但 OpenSBI 使用了该扩展的指令

**trap_trace.log 统计**:
```
mcause=0x00000000: 1 次 (初始 reset)
mcause=0x00000002: 83 次 (非法指令)
mcause=0x0000000c (12): 0 次 (instruction page fault) ← 手册关注的，未出现
mcause=0x0000000d (13): 0 次 (load page fault) ← 手册关注的，未出现
mcause=0x0000000f (15): 0 次 (store page fault) ← 手册关注的，未出现
```

### 问题 2: OpenSBI 卡在 80020xxx 循环，无法进入 Linux kernel

**严重程度**: 高  
**状态**: 已确认  

在 83 次非法指令异常处理后，OpenSBI 进入 0x80020e28 ~ 0x80021910 范围内的循环。  
从 cycle ~11M 到 25.5M+（14M+ cycles），PC 始终在此范围内循环，未进入 Linux kernel (0x80400000+)。

**FIFO-MON PC 范围分析** (cycle 500K ~ 25.5M):
- 所有 PC 值均在 0x80020e28 ~ 0x80022788 范围内
- 未观察到 PC=0x804xxxxx (Linux kernel)
- 未观察到 PC=0xC037xxxx (Sv32 虚拟空间)

**可能原因**:
- OpenSBI 在等待 UART 输入（rx_fifo_count=0 始终为 0）
- OpenSBI 在轮询某个硬件状态（如 timer、PLIC）
- 非法指令导致 OpenSBI 初始化不完整，进入死循环
- 某个外设未正确响应导致 OpenSBI 阻塞

### 问题 3: GPIO 数据始终未定义 (gpio_data=0xzzzz)

**严重程度**: 中  
**状态**: 已确认  

所有 FIFO-MON 条目中 `gpio_data=0xzzzz`（Hi-Z / 未定义）。  
这表示 GPIO 外设输出从未被驱动到有效值。

**可能原因**:
- GPIO 初始化代码未执行（被非法指令异常跳过）
- GPIO 硬件模块存在问题
- 仿真中 GPIO 输入未连接

### 问题 4: UART RX FIFO 始终为空

**严重程度**: 低  
**状态**: 符合预期（SRAM 模式）  

`rx_fifo_count=0` 始终为 0，`rx_state=0` 始终为 0。  
这是预期的，因为 linux_boot 任务使用 blhex+phex (SRAM 模式)，不通过 UART 加载程序。  
但 OpenSBI 可能在轮询 UART 等待 console 输入，导致阻塞。

### 问题 5: trap_trace.log 在 84 条目后停止增长

**严重程度**: 中  
**状态**: 已确认  

trap_trace.log 最后修改时间 22:12:17，此后 16+ 分钟无新条目。  
这表示 OpenSBI 在 83 次非法指令异常后不再触发新的异常，进入无异常的循环。

### 问题 6: 仿真 runtime 过长

**严重程度**: 中  
**状态**: 已确认  

tasks.yaml 中 linux_boot 的 runtime=60s（仿真时间）。  
在 100MHz 时钟下，60s = 6B cycles。当前速度 ~21.7K cycles/s，完整运行需要 ~76 小时。  
实际有用的仿真可能在 50-200M cycles 处到达故障点，但 OpenSBI 卡住后无法到达。

1. **分析非法指令**: 用 `--debug trace,trap` 重新仿真前 11M cycles，捕获具体哪条指令被判定为非法
