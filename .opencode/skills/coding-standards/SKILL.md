# CPU RTL coding standards

Keep the design easy to inspect. Prefer direct state machines, explicit registers and visible
handshakes over clever encodings, generated indirection or premature performance machinery.

## Start from the current design

1. Read the complete module and its direct caller before editing it.
2. Search every changed port, parameter, macro and hierarchical testbench reference with `rg`.
3. Preserve the project boundary: single-core, in-order, multi-cycle, single-issue RV32IMA.
4. Preserve the blocking two-way caches, two-way ITLB/DTLB, Sv32 PTW, CLINT, PLIC and AXI/APB
   paths unless the task explicitly changes their behavior.
5. Avoid broad interface renames while fixing behavior. Make one functional idea visible per diff.

## Write plain SystemVerilog

- Use `lower_snake_case` for modules, instances and signals.
- Use `UPPER_SNAKE_CASE` for parameters, localparams, states and macros.
- Use `logic` for RTL state and combinational signals; retain `wire` where an existing wrapper is
  deliberately written in Verilog/net style.
- Use `always_ff` for sequential state and `always_comb` for combinational decisions.
- Give every combinational output a default before conditional overrides. Avoid inferred latches.
- Use nonblocking assignments in sequential blocks and blocking assignments in combinational blocks.
- Use sized constants at protocol and address boundaries. Make width extension or truncation explicit.
- Keep state encodings readable with an enum or named localparams. Do not encode unrelated flags into
  state bits to save a handful of flops.
- Use ordinary `for` loops with an integer index when clearing arrays or scanning ways. Keep loop
  bounds static and synthesis-friendly for Vivado 2018.3.
- Keep `initial`, `$display`, `$fwrite`, force/release and delays in testbench or simulation-only code.
- Keep generated headers such as `src/rtl/core/cache_def.svh` generated by their tool; change the
  source configuration and regenerate instead of hand-editing derived values.

## Reset and clock domains

- Follow the surrounding interface's active-low reset name: normally `resetn`, with protocol-specific
  names such as `aresetn`, `PRESETn` or `rst_n` where already established.
- Implement state reset as asynchronous assertion with the existing pattern:

```systemverilog
always_ff @(posedge clk or negedge resetn) begin
    if (!resetn)
        state <= IDLE;
    else
        state <= next_state;
end
```

- Use `src/rtl/common/reset_sync.sv` once per target clock domain when an asynchronous reset crosses
  into that domain. Treat its output as asynchronous assert, synchronous deassert.
- Never pass pulses, multi-bit state or ready/valid transactions across a clock domain by independently
  synchronizing bits. Use the existing AXI CDC or an explicit request/acknowledge scheme.
- Keep DDR reset release dependent on MIG calibration. Do not let the CPU issue memory traffic before
  its destination clock domain and reset are ready.

## Preserve handshake meaning

- Treat a ready/valid transfer as occurring only on `valid && ready` in the same cycle.
- Hold payload, ID and control stable while `valid && !ready`.
- Do not make a valid signal combinationally depend on the peer's ready signal unless the existing
  protocol block explicitly requires it and has no combinational loop.
- Keep AXI read, write-address, write-data and response channels independent.
- Match a response to the captured request. Latch address, size, privilege and fault metadata before
  a multi-cycle Cache, PTW, multiplier/divider or bus operation begins.
- Give exceptions and interrupts an explicit priority. Do not allow a pending interrupt to discard an
  in-flight instruction result.

## Cache, TLB and MMU changes

- Separate lookup, miss/refill/walk and response states visibly.
- Update tag, valid, replacement and data state at one well-defined completion point.
- Keep DCache write-through semantics: a store is complete only according to the downstream response,
  not merely because a cached word was updated.
- Keep `fence.i`, `sfence.vma`, superpage matching and PTE A/D updates explicit in control flow.
- Do not add non-blocking Cache machinery, extra outstanding requests or speculative state as a cleanup.
- Add assertions or focused self-checking tests for metadata captured across stalls and faults.

## Testbench discipline

- Name a module testbench `tb_<subject>` and give it ``timescale 1ns / 1ps``.
- Prefer self-checking tasks and the x28–x31 framework protocol over manual waveform inspection.
- End a passing test as soon as its report is available. Keep a bounded timeout as the failure path.
- Print `PASS`/`FAIL` and enough request, response, PC or trap context to reproduce a failure.
- Put reusable SoC testbench helpers in `src/tb/tb_soc_includes.svh`; avoid fragile bind layers and
  image-specific hierarchical probes.
- Keep normal simulation free of WDB/VCD. Enable traces or waves only for a focused investigation.

## Validate proportionally

Run cheap checks after each coherent edit:

```bash
git diff --check
python3 tools/test_builder.py --test <category/name>
```

Then run the smallest task that exercises the changed boundary:

```bash
python3 -m tools.vivado_cli -task <task> -create -sim
```

After several related RTL changes, run the shared short plan once:

```bash
python3 -m tools.vivado_cli -batch-plan config/short_regression.yaml
```

Reserve FPGA bitstream generation and long Linux/DDR3 simulation for a grouped validation point.
Do not claim Linux boot success from compile/elaboration smoke alone.
