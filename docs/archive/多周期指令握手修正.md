# 多周期指令握手修正

在commit `1cc7d7bd2c129b51fac87b4f68592b5e195f6c3f` 中，我们修正了多周期指令握手逻辑，修复了乘除法会一直重复执行的问题。

## 原先的握手逻辑

```verilog
// 乘除法启动控制
  always @(posedge clk or posedge reset)
  begin
    if (reset)
    begin
      mul_start <= 1'b0;
      div_start <= 1'b0;
      mul_src1_reg <= 32'b0;
      mul_src2_reg <= 32'b0;
      div_src1_reg <= 32'b0;
      div_src2_reg <= 32'b0;
    end
    else
    begin
      // 乘法启动
      if (alu_mul && !mul_start)
      begin
        mul_start <= 1'b1;
        mul_src1_reg <= src1;
        mul_src2_reg <= src2;
      end
      else if (mul_done)
      begin
        mul_start <= 1'b0;
      end

      // 除法启动
      if (alu_div && !div_start)
      begin
        div_start <= 1'b1;
        div_src1_reg <= src1;
        div_src2_reg <= src2;
      end
      else if (div_done)
      begin
        div_start <= 1'b0;
      end
    end
  end
```

这段代码在特定条件下会导致乘法重复计算。如下：

+ 当alu_mul持续为高且mul_start为低时，mul_start会在时钟上升沿置1，启动乘法运算。
+ 乘法完成后，mul_done变高，在下一个时钟上升沿将mul_start清零。
+ 由于alu_mul仍然为高，而mul_start已清零，在下一个时钟上升沿又会满足alu_mul && !mul_start条件，从而再次将mul_start置1，启动一次新的乘法。

这样循环下去，只要alu_mul保持为高，且mul_done能周期性地完成，乘法器就会不断重复计算。

## GPT修改后的逻辑

重构了乘除法握手控制，从“控制位电平触发”改为“单拍触发+忙闲状态+再次触发闸门”。
> 参考 alu_32bit.v:131, alu_32bit.v:165, alu_32bit.v:184, alu_32bit.v:209。

增加了乘除法结果锁存与done稳定保持逻辑，避免完成后结果/完成信号抖动。
> 参考 alu_32bit.v:173, alu_32bit.v:198, alu_32bit.v:244, alu_32bit.v:269。

> 参考 alu_display.v:17, alu_display.v:35, alu_display.v:112。
